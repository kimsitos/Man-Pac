# Man-Pac

A complete, playable Pac-Man clone written in Python with [pygame-ce](https://pyga.me/). Mazes are generated by an external **A-Maze-ing** package (`mazegenerator`), the game is configured through a JSON file with comments, and scores are persisted in a local JSON highscore file.

## Description

**Man-Pac** recreates the classic arcade game Pac-Man (Namco, 1980). The player moves through a maze, eats every pacgum to clear the level, avoids four ghosts and can turn the tables by eating a super-pacgum, which makes the ghosts edible for a few seconds.

The goal of the project is to build a full game loop (*Main menu → Play → Win or Lose → Enter name for highscore → Main menu*) with a clean, modular, object-oriented architecture, strict typing and a robust error-handling strategy.

Overview:

- 10 levels (configurable, minimum 10), each with a time limit.
- Mazes generated by the assigned external `mazegenerator` package (`perfect=False`, so the mazes have loops and no dead ends).
- 4 ghosts (one per corner), 4 super-pacgums (one per corner), player starting in the middle.
- Persistent top 10 highscores.
- Cheat mode for peer review.
- Typed (`mypy`), linted (`flake8`) and documented (docstrings, NumPy style) code.

## Instructions

### Requirements

- Python **3.14** or later (see `requires-python` in `pyproject.toml`).
- [`uv`](https://docs.astral.sh/uv/) as package manager (`pip install uv` if it is not installed).
- A graphical environment (the game opens a pygame window).

Dependencies (managed through `pyproject.toml` / `uv.lock`):

| Package | Purpose |
|---|---|
| `pygame-ce` | Window, drawing, input and sprites |
| `pydantic` | Configuration validation and highscore records |
| `mazegenerator` | External A-Maze-ing package, installed as-is from `lib/mazegenerator-2.1.0-py3-none-any.whl` |
| `flake8`, `mypy` | Linting and static type checking |

### Makefile rules

```bash
make install          # install dependencies (uv sync)
make run              # python3 pac-man.py config.json
make run_cheat_mode   # same, with the cheat mode enabled
make debug            # run the game under pdb
make lint             # flake8 + mypy (flags required by the subject)
make clean            # remove caches (.mypy_cache, __pycache__)
```

### Running manually

```bash
uv sync
uv run python3 pac-man.py config.json
# with cheat mode
uv run python3 pac-man.py config.json --cheat_mode
```

The program takes the configuration file as its argument. If the file is missing, cannot be read or is invalid, a clear message is printed and the program exits without a Python traceback.

### Controls

| Key | Action |
|---|---|
| `W` `A` `S` `D` / arrow keys | Move |
| `Esc` | Pause / resume |
| Mouse | Navigate the menus |
| Keyboard | Type your name on the game-over / victory screens (`Enter` to save, `Backspace` to delete) |

Cheat mode keys (only with `--cheat_mode`):

## Features

- **Main menu**: Play, High Score, Instructions, Quit.
- **In-game HUD**: score, lives, current level and remaining time.
- **Pause menu**: Continue or return to the main menu (the level timer is paused too).
- **Game over screen** and **victory screen**: final score and name input to save the score.
- **Instructions screen**: controls and rules.
- **Ghost behaviour**: chase the player, flee when edible, return to their corner when eaten.
- **Progression**: the score and the remaining lives are kept between levels.

## Configuration

The game is configured through a JSON file passed as the only command-line argument (`config.json` is provided).

**Comments**: lines starting with `#` (and blank lines) are ignored before the JSON is parsed.

### Example

```jsonc
{
    # Basic stats
    "lives": 3,
    "seed": 0,
    "level_max_time": 90,

    # Points
    "points_per_pacgum": 10,
    "points_per_super_pacgum": 20,
    "points_per_ghost": 50,

    # Levels
    "levels": [
        { "width": 15, "height": 15 },
        { "width": 15, "height": 15 }
        # ... at least 10 levels
    ]
}
```

### Keys and defaults

| Key | Type | Default | Constraint | Description |
|---|---|---|---|---|
| `lives` | int | `3` | `> 0` | Lives at the start of the game |
| `seed` | int | `0` | – | Maze seed. `0` produces a random maze; a value `> 0` makes generation reproducible |
| `level_max_time` | int | `90` | `> 0` | Time limit per level, in seconds |
| `points_per_pacgum` | int | `10` | `> 0` | Points for a pacgum |
| `points_per_super_pacgum` | int | `20` | `> 0` | Points for a super-pacgum |
| `points_per_ghost` | int | `50` | `> 0` | Points for an edible ghost |
| `levels` | list | 10 levels of 15×15 | at least 10 items | One entry per level |
| `levels[].width` | int | `15` | `> 2` | Maze width in cells |
| `levels[].height` | int | `15` | `> 2` | Maze height in cells |

### Error handling

- Missing keys fall back to the defaults above.
- Unknown keys are ignored.
- A missing file, a permission error, malformed JSON or an out-of-range value prints an explicit error message and stops the program cleanly (exit code 1), never a traceback.

## Highscore

### How it works

- Scores are stored in `high_scores.json`, at the root of the project, as a list of records:

  ```json
  [
      { "name": "Sara", "scored": 229 },
      { "name": "Nico", "scored": 222 }
  ]
  ```

- Only the **top 10** scores are kept, sorted from highest to lowest.
- The highscores are read from disk every time they are needed (highscore screen, end of the game) and written back whenever a new record is added.
- When the game ends (victory or game over), the final score is shown. If it beats the lowest score of the list (or the list is not full), the player can click **New Score** and type a name.
- Names are limited to **10 characters**, **alphanumeric and spaces only** (other keys are ignored while typing). Scores are non-negative integers (the score never decreases).
- Each record is validated with a `pydantic` model (`Player`), and a corrupt or missing file produces a clear error message.
- The top 10 is displayed in the **High Score** screen of the main menu (and reachable from the end-game screens with *Check top 10*).

### Why this design

A plain JSON file is human-readable, needs no extra dependency, is easy to inspect or reset during peer review, and maps naturally to a `pydantic` model, which gives free validation of the structure and types of every record.

## Maze Generation

Mazes are **not generated by this project**: they come from the A-Maze-ing package assigned to us (`mazegenerator`), installed **as-is** from `lib/mazegenerator-2.1.0-py3-none-any.whl` (declared in `pyproject.toml` through `[tool.uv.sources]`). Our code adapts to its interface, never the opposite.

Usage (see `src/maze_class.py`):

1. `Maze` receives the list of levels and the seed from the configuration.
2. For each level it calls `MazeGenerator(size=(width, height), seed=seed)`. The `perfect` parameter is left at its default, `False`, which produces **Pac-Man-compatible mazes**: loops are added and there are no dead ends, so the player can never be trapped.
3. The generator returns a grid (`generator.maze`) where each cell is a 4-bit mask of walls: `North = 1`, `East = 2`, `South = 4`, `West = 8`. A cell with value `15` is a fully closed cell (the "42" pattern): it is drawn in yellow and gets no pacgum.
4. `Maze` draws the walls on a `pygame.Surface` (cells of 50 px) and exposes helpers used by the entities: wall collision, neighbours of a cell, Dijkstra distance map and shortest path.

If the generator fails, the error is handled by the top-level handlers in `pac-man.py` so the game never ends with a traceback.

## Implementation

### Game loop and screens

`GameScheduler` (`src/scheduler.py`) owns the main loop (60 FPS). Each screen is a subclass of `ScreenBase` and implements `event_cacher()`, `change_screen()` and `render()`. Screens never switch directly: they *request* a state (`request_state_change`) and the scheduler consumes it and performs the transition (resizing the window, pausing/resuming the timer, starting a new game, passing the score to the end screens…). The available states are `MENU`, `PLAY`, `MENU_GAME` (pause), `HIGH_SCORE`, `INSTRUCTIONS`, `LOST_GAME` and `WIN_GAME`.

### Movement

Everything lives on a 50 px grid and entities move 2 px per frame. Only when an entity is exactly centred in a cell can it change direction, and only if the wall mask of that cell allows it. The player stores a *wanted direction* from the keyboard and turns as soon as the maze allows it.

### Ghosts

Each ghost is a small state machine (`NONEATABLE`, `EATEABLE`, `RETURN_TO_BASE`):

- **Not edible**: at every cell it picks, at random, either the neighbour that is closest to the player (using a Dijkstra distance map computed from the player's position) or a random direction. This keeps them threatening but not perfectly predictable.
- **Edible** (5 seconds after a super-pacgum): it picks the neighbour that is *farthest* from the player, so it runs away. It is drawn tinted red.
- **Return to base**: once eaten, it follows the shortest path back to its corner and becomes dangerous again when it arrives.

### Rules

- Eating a pacgum / super-pacgum / ghost gives the points set in the configuration.
- Touching a non-edible ghost costs one life; every entity returns to its starting position. With no lives left the game is over.
- A level is won when all pacgums are eaten; the next maze is generated and the window is resized to fit it. After the last level the victory screen is shown.
- If the level timer reaches zero, the player loses a life, entities return to their starting position and the timer restarts. With no lives left, the game is over.
- Pausing stops the level timer.

### Quality

- `flake8` and `mypy` (flags from the subject) via `make lint`.
- Type hints and NumPy-style docstrings across the code base.
- Errors (missing config, invalid values, missing sprites, highscore file problems) are caught and reported with a clean message.

## General Software Architecture

```
Man-Pac/
├── pac-man.py              # Entry point: python3 pac-man.py config.json
├── config.json             # Example configuration (JSON with # comments)
├── high_scores.json        # Persistent top 10
├── Makefile
├── pyproject.toml / uv.lock
├── lib/
│   └── mazegenerator-2.1.0-py3-none-any.whl   # Assigned A-Maze-ing package
├── assets/sprites/         # Sprites and backgrounds
└── src/
    ├── scheduler.py          # GameScheduler: main loop and screen transitions
    ├── parse_config_file.py  # Config / Level pydantic models + parser
    ├── maze_class.py         # Maze: wraps mazegenerator, drawing, pathfinding
    ├── cheat_mode.py         # Cheat_Mode: --cheat_mode flag and cheat keys
    ├── entitys/
    │   ├── entity_base.py    # Entity (ABC): movement, wall collision, Direction
    │   ├── man_pac.py        # PacMan: input, score, lives
    │   ├── ghost.py          # Ghost: states, chase / flee / return to base
    │   └── gumpac.py         # Gumpac and SuperGumpac sprites
    └── screens/
        ├── screen_base.py    # ScreenBase (ABC) and ScreenState enum
        ├── menu.py           # Main menu
        ├── menu_game.py      # Pause menu
        ├── game_screen.py    # GameScreen: levels, collisions, timer
        ├── hub_screen.py     # HUD (score, lives, level, time)
        ├── high_score.py     # Top 10 screen + load/save helpers
        ├── instructions_screen.py
        ├── win_game.py       # Victory screen + name input
        └── lost_game.py      # Game-over screen + name input
```

Relationships:

- `pac-man.py` creates a `GameScheduler`, which parses the configuration (`parse_config_file`) and builds one instance of every screen.
- `GameScreen` owns the `Maze`, the `PacMan`, the four `Ghost` and the `Gumpac` / `SuperGumpac` sprite groups, the `Hubs` (HUD) and the `Cheat_Mode`.
- `Entity` is the abstract base of `PacMan` and `Ghost`; `Gumpac` and `SuperGumpac` are plain sprites.
- `Ghost` uses `Maze` to compute distance maps and shortest paths.
- `Win_Game` and `Lost_Game` use the helpers of `high_score.py` (`is_high_score`, `new_record`, `Player`) to save scores.
